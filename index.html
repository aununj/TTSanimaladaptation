Crossword Battle: Coordinate Repair

MISSION

Repair the crossword grid coordinate system to eliminate all letter intersection conflicts. This is a targeted technical repair, NOT a complete application redesign or rebuild.

CRITICAL INSTRUCTIONS

  • Preserve all existing 30 clues and official answers.
  • Preserve all unique IDs, directions, and clue numbers.
  • Preserve the existing two-screen gameplay design.
  • Preserve all six groups and the five-round rotation.
  • Preserve the existing scoring system and leaderboard.
  • Preserve animations, timer, answer key, and progress tracking.
  • Do not redesign the interface.
  • Do not remove or simplify existing game features.
  • Do not disable crossword validation to hide errors.

1. REBUILD CROSSWORD COORDINATES

Recalculate the row and column coordinates for all 30 crossword entries using a valid crossword placement algorithm.

  • Across words must be placed horizontally.
  • Down words must be placed vertically.
  • Every intersecting cell must contain exactly the same letter.
  • No conflicting letters are allowed.
  • No unintended word overlaps are allowed.
  • All words must remain within the grid boundaries.
  • Keep the crossword compact and readable.
  • Do not blindly reuse the existing coordinates.

2. SINGLE CANONICAL GRID

Implement one canonical crossword grid shared by all Across and Down entries.

  • Each physical cell must have one authoritative letter.
  • Across and Down entries must reference the same shared cells.
  • Never maintain independent conflicting letter copies.
  • Revealed letters must never change.

3. VALIDATION BEFORE GAME START

Run a complete validation of all 30 entries before allowing the battle to start.

Required validation report:

  • Across entries: 15
  • Down entries: 15
  • Total entries: 30
  • Conflicting intersections: 0
  • Invalid coordinates: 0
  • Invalid word lengths: 0
  • Unintended overlaps: 0
  • All answers revealable: TRUE
  • Validation status: PASS

If validation fails, block the game from starting and display the exact conflicting entry IDs, coordinates, and letters.

4. ANSWER SUBMISSION AND REVEAL LOGIC

  • Correct answer: +10 points.
  • Incorrect answer: 0 points.
  • Always reveal the official correct answer after submission.
  • Never insert an incorrect student submission into the grid.
  • Reveal all letters atomically, or reveal none if validation fails.
  • Mark the clue as completed after submission.
  • Completed clues cannot be selected again.
  • Previously revealed letters must remain unchanged.

5. REGRESSION TESTS

Test all of the following scenarios:

  1. Answer an Across clue first, then its intersecting Down clue.
  2. Answer a Down clue first, then its intersecting Across clue.
  3. Reveal all 30 answers in randomized order.
  4. Test entries with multiple intersections.
  5. Submit an incorrect student answer.
  6. Reset the game and replay.
  7. Verify that all scores and group turns remain correct.

6. GAMEPLAY MUST REMAIN UNCHANGED

  • Six groups.
  • Five members per group.
  • Five rounds.
  • Thirty total turns.
  • Fixed group rotation.
  • Each group selects any unanswered Across or Down clue.
  • Maximum 50 points per group.
  • Maximum 300 points overall.

7. FINAL ACCEPTANCE CRITERIA

Do not declare the repair complete until all 30 crossword entries pass validation with zero conflicting intersections.

The final result must preserve the existing visual design, gameplay, scoring engine, and user experience.

This task is strictly a crossword coordinate and consistency repair. Do not rebuild the application from scratch.
